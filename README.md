# MC Panel

**العربية** | [English](README.en.md)

متوافقة مع كل إصدارات ماينكرافت من **1.13 حتى 26.3** وما بعدها (مُحدّثة لأحدث إصدار 26.3). اللوحة نفسها لا تعتمد على إصدار اللعبة، وتقرأ ملفات اللاعبين بصيغتيها القديمة والجديدة (مجلد `players/` الجديد في 26.1+ والقديم `playerdata/`).

لوحة تحكم ويب لإدارة سيرفر Minecraft (Paper/Spigot) من المتصفح، بدل الدخول بـ SSH كل مرة. تتحكم بالسيرفر عن طريق جلسة tmux، وتعرض الكونسول واللوق مباشرة عبر WebSocket.

## المميزات

- تشغيل، إيقاف، وإعادة تشغيل السيرفر
- إعادة تشغيل تلقائي لو السيرفر طاح من نفسه (كراش، OOM، الخ)، بدون إعادة تشغيل لو الإيقاف كان مقصود من اللوحة
- كونسول مباشر: إرسال أوامر ومتابعة اللوق لحظيًا
- إحصائيات لحظية كل ثانية: TPS، استهلاك الرام والمعالج (CPU)، مدة التشغيل
- إدارة اللاعبين: op، deop، ban، kick، pardon
- عرض قوائم المشرفين (ops)، المحظورين، والـ whitelist
- مدير ملفات كامل: تصفح، فتح وتعديل، رفع، تنزيل، حذف. الوصول محصور داخل مجلد السيرفر فقط
- نسخ احتياطي: إنشاء نسخة (العوالم + server.properties + ops/whitelist/bans)، استرجاع، حذف، تنزيل. النسخة تُؤخذ بعد `save-all flush` مع إيقاف الحفظ التلقائي مؤقتاً ليكون العالم متّسقاً
- **مستخدمون بصلاحيات تفصيلية**: لكل ميزة في اللوحة صلاحية مستقلة (نحو 34 صلاحية في 9 أقسام: السيرفر، الكونسول، اللاعبون، الملفات، النسخ الاحتياطية، المهام المجدولة، الإضافات، الإعدادات، إدارة اللوحة). تختار لكل مستخدم ما تريد بالضبط، والقوالب الجاهزة (مشاهد / مراقب / مدير) مجرد اختصار يملأ الخانات وتعدّلها بعده. تُفرض على السيرفر في كل طلب وتسري فوراً، وأوامر الكونسول تُفحص كل أمر حسب صلاحيته. المستخدم الذي يملك إدارة المستخدمين لا يستطيع منح ما لا يملكه. المالك هو حساب `.env` وله كل شيء ولا يُحذف. **سجل نشاط** يسجّل الدخول والأوامر وتغييرات الملفات والنسخ والإعدادات والمستخدمين ومحاولات الدخول الفاشلة والممنوعة (دون كلمات المرور أو محتوى الملفات). اتصال WebSocket يتطلب جلسة مسجّلة أيضاً
- **مراقبة تاريخية**: رسوم لـ TPS والذاكرة والمعالج واللاعبين والقرص الحر لآخر 24 ساعة (نقطة كل دقيقة، تُحفظ في `.panel-history.json`)، بلا مكتبات رسم
- **تنبيهات** إلى Discord وTelegram: توقف السيرفر غير المتوقع، **إيقافه عمداً (خيار مستقل)**، تشغيله، انخفاض TPS، ارتفاع الذاكرة، امتلاء القرص، مع فاصل بين التنبيهات المتكررة. رابط Discord محصور بنطاقات discord.com، والمفاتيح لا تُعاد كاملة من الـ API
- **صفحة «حول» وتحديث اللوحة من داخلها**: تعرض الإصدار والنظام، وتفحص GitHub عن إصدار مستقر جديد أو أحدث كود (main)، وتحدّث بضغطة: تنزيل من GitHub، حفظ نسخة من الملفات المستبدلة في `.panel-updates`، تثبيت الاعتماديات فقط إن تغيّرت، والرجوع تلقائياً إن فشلت خطوة، ثم إعادة تشغيل نفسها (مع systemd أو pm2 أو دونهما). لا يُستبدل `.env` ولا بياناتك. في Docker يكون التحديث بسحب الصورة. صلاحية مستقلة «تحديث اللوحة» (للمالك افتراضياً)
- **نسخ احتياطي خارجي** من صفحة النسخ الاحتياطية ← النسخ الخارجية: **Backblaze B2** وAmazon S3 والمتوافقة (Wasabi وCloudflare R2 وMinIO وDigitalOcean) وSFTP وFTP وWebDAV (Nextcloud) وGoogle Drive وDropbox وAzure Blob وأي وجهة rclone جاهزة. تضيف وجهة واحدة أو أكثر وتتحقق من الاتصال بزر، ثم تختار لكل نسخة يدوية أو مهمة مجدولة أين تُرسل وهل تبقى نسخة محلية، مع الإبقاء على آخر N نسخة في الوجهة. تحتاج rclone مثبتاً على السيرفر. مفاتيحك تُمرَّر إلى rclone عبر متغيرات بيئة ولا تظهر في سطر الأوامر ولا تُعاد للمتصفح
- **تحقق ثنائي (TOTP)** لكل حساب (Google Authenticator وAuthy...)، مع منع إعادة استخدام الرمز، وخيار `COOKIE_SECURE` للكوكي خلف HTTPS
- **مدير الإضافات**: عرض الإضافات المثبّتة (الاسم والإصدار من `plugin.yml`)، تفعيل/تعطيل/حذف، **بحث وتثبيت من Modrinth أو Hangar (متجر Paper الرسمي)، و**تحديث الإضافات** إلى أحدث إصدار متوافق (فردياً أو الكل، مع حفظ النسخة القديمة)** باختيار نسخة متوافقة مع إصدار السيرفر والتحقق من hash الملف قبل حفظه
- **إصدار السيرفر والتحديث**: يعرض إصدار ماينكرافت والبناء (build) الحالي، ويفحص PaperMC ويخبرك بوجود تحديث، وبضغطة واحدة يأخذ نسخة احتياطية ثم يوقف السيرفر ويبدّل الملف (القديم يُحفظ في `.panel-old-jars`) ويشغّله. ويمكنك تنزيل أي إصدار أو **بناء محدد** مع التحقق من checksum، وتسجيل `eula=true` فقط إذا وافقت صراحة
- **حظر مؤقت** بمدة وسبب: يُرفع الحظر تلقائياً عند انتهاء المدة (حتى بعد إعادة تشغيل اللوحة)
- **مهام مجدولة** تعمل على السيرفر حتى لو أُغلقت الصفحة (يومي، أسبوعي بأيام تختارها، شهري، متكرر كل N دقيقة/ساعة، **أو لمرة واحدة** تنتهي بعد تنفيذها، وcron للمتقدمين): نسخ احتياطي مع الاحتفاظ بآخر N نسخة، إعادة تشغيل مع عدّاد تنازلي يظهر للاعبين في الشات، أوامر، ورسائل بث. تُحفظ في `.panel-schedule.json` ولا تضيف مكتبات ولا ذاكرة تُذكر
- تعديل server.properties وإعدادات الذاكرة/JVM (Xms، Xmx، G1GC، فلاقز إضافية) من الواجهة مباشرة
- تسجيل دخول بمستخدم واحد، الباسورد مشفر بـ bcrypt، مع حد أقصى لمحاولات الدخول الفاشلة
- واجهة عربية بالكامل (RTL)، فيها وضع داكن ووضع فاتح
- أوامر `tps` و`list` الداخلية (لتحديث TPS وقائمة اللاعبين) لا تظهر في الكونسول، تصل نتيجتها للواجهة مباشرة
- سجل دائم لكل من دخل السيرفر (وليس فقط المتصلين الآن)، مع تبويب "كل اللاعبين"
- صفحة تفاصيل لاعب مستقلة (وليست نافذة منبثقة): الصحة والخبرة مع أزرار علاج/تغذية/قتل مباشرة، المخزون والدروع واليد الثانية بأيقونات حقيقية مطابقة للعبة، صندوق سحري منفصل، الموقع، الإحصائيات الكاملة، سجل أماكن الموت والانتقال، وحذف بيانات اللاعب بشكل انتقائي (مخزون/صندوق سحري/خبرة/إحصائيات/تقدم/سجل اللوحة) — البيانات الحية للمتصلين (بما فيها الإحصائيات) وسجل الموت/الانتقال يحتاجان إضافة PanelDataLogger المرفقة (انظر أدناه)
- مدير ملفات: الصف كامل قابل للنقر للفتح، والإجراءات الثانوية (تنزيل، إعادة تسمية، حذف) داخل قائمة ⋮
- إعدادات server.properties موسّعة تغطي نحو 50 خاصية مصنّفة في فئات، بالإضافة لقسم "خصائص إضافية" يحرّر أي مفتاح آخر في الملف دون الحاجة لفتح مدير الملفات إطلاقاً

## المتطلبات

- Linux مع tmux مثبت
- Node.js إصدار 18 فأعلى
- Java مناسبة لإصدار سيرفر ماينكرافت الذي تشغّله (مثلاً Java 21 لـ 1.21.x وJava 25 لـ 26.x). اللوحة نفسها تعمل على Node.js فقط ولا تحتاج Java
- سيرفر Paper/Spigot جاهز مسبقًا (أي إصدار من 1.13 فما فوق، المثال في `.env` هو 26.3): ملف jar وعوالمه موجودين في مجلد على الجهاز

اللوحة لا تُنزّل أو تُعدّ سيرفر Minecraft لك، هي فقط تدير سيرفر موجود مسبقًا.

## التثبيت

```bash
git clone https://github.com/tlomts-dev/mcpanel panel
cd panel
npm install
cp .env.example .env
```

بعدين افتح ملف `.env` وعدّل القيم، خصوصًا `MC_DIR` (مسار سيرفر Minecraft الفعلي)، `MC_JAR` (اسم ملف الـ jar)، و`ADMIN_PASS`.

> **تحديث على نسخة موجودة عندك؟** بعد `git pull` نفّذ `npm install` من جديد —
> أُضيفت تبعية جديدة (`prismarine-nbt`) لقراءة ملفات اللاعبين. بدونها تعمل
> اللوحة بشكل طبيعي، فقط تبويب "المخزون/الموقع الحالي" بصفحة تفاصيل اللاعب
> يظهر معطّلاً مع رسالة توضيحية.
>
> لبيانات اللاعبين **المتصلين** الحية (مخزون/موقع/صحة فوري بلا انتظار حفظ)،
> ركّب إضافة `PanelDataLogger` المرفقة (انظر قسمها أدناه) واضبط `PANEL_HTTP_PORT`
> في `.env` ليطابق منفذها. بدونها، تُقرأ هذه البيانات من آخر ملف محفوظ فقط.

## التشغيل

```bash
npm start                 # اللغة الافتراضية من PANEL_LANG (ar افتراضياً)
PANEL_LANG=en npm start   # الإنجليزية كلغة افتراضية
```

الواجهة بلغتين (العربية RTL والإنجليزية LTR) من نسخة واحدة وملفات لغة. يغيّر كل مستخدم لغته من القائمة في الأعلى (أو في صفحة الدخول) وتُحفظ في كوكي، و`PANEL_LANG` هي اللغة الافتراضية فقط. رسائل الأخطاء من السيرفر تأتي بلغة المستخدم أيضاً.

اللوحة تفتح على المنفذ المحدد في `PORT` (افتراضيًا 8080):

```
http://<عنوان-الجهاز>:8080
```

سجّل الدخول بـ `ADMIN_USER` و`ADMIN_PASS` من ملف `.env`.

للتشغيل الدائم في بيئة إنتاج، استخدم مدير عمليات بدل تشغيل الأمر مباشرة في الطرفية:

```bash
npm install -g pm2
pm2 start server.js --name mc-panel
pm2 save
```

## متغيرات البيئة

| المتغير | الوصف | الافتراضي |
|---|---|---|
| `PORT` | منفذ اللوحة | `8080` |
| `MC_DIR` | مجلد سيرفر Minecraft (فيه الـ jar والعوالم)، مستقل عن مكان اللوحة | `/opt/minecraft` |
| `MC_JAR` | اسم ملف jar السيرفر بالضبط (يُعاد قراءته من `.env` عند كل تشغيل للسيرفر، دون إعادة تشغيل اللوحة) | `spigot-26.3.jar` |
| `TMUX_SESSION` | اسم جلسة tmux اللي يشتغل فيها السيرفر | `mcserver` |
| `SESSION_SECRET` | مفتاح تشفير الجلسات. لو فاضي، يتولد عشوائي عند كل تشغيل، فيسجل خروج الجميع بعد كل إعادة تشغيل للوحة | عشوائي |
| `ADMIN_USER` | اسم مستخدم الدخول | `admin` |
| `ADMIN_PASS` | كلمة المرور، نص عادي | - |
| `ADMIN_HASH` | هاش bcrypt جاهز للباسورد، يستخدم بدل `ADMIN_PASS` لو موجود | - |
| `SERVER_NAME` | الاسم الذي يظهر في رسائل التنبيهات | اسم مجلد `MC_DIR` |
| `COOKIE_SECURE` | `true` أو `auto` لإرسال كوكي الجلسة عبر HTTPS فقط (استعمل `auto` خلف Caddy/nginx) | معطّل |
| `PANEL_LANG` | لغة الواجهة الافتراضية (`ar` أو `en`) | `ar` |
| `RCLONE_BIN` | مسار برنامج rclone للنسخ الخارجي | `rclone` |

توليد `SESSION_SECRET`:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

توليد `ADMIN_HASH` بدل تخزين الباسورد كنص صريح:
```bash
node -e "console.log(require('bcryptjs').hashSync('كلمة-المرور-هنا', 12))"
```

## إضافة PanelDataLogger — بيانات حية + أماكن الموت والانتقال

هذه الإضافة (مجلد `PanelDataLogger/` بجانب هذا المشروع) لها مهمتان:

1. **خادم HTTP داخلي (`127.0.0.1` فقط)** يقدّم مخزون/موقع/صحة أي لاعب
   **متصل الآن** مباشرة من كائنه في الذاكرة — بديل أدق وأسرع بكثير من
   انتظار Minecraft يحفظ ملفه على القرص. بدون هذه الإضافة، تُقرأ هذه
   البيانات من آخر ملف محفوظ فقط (قد يتأخر حتى أول `/save-all` أو مغادرة).
2. **تسجيل إحداثيات الوفاة والانتقال** في الكونسول (مخفية عنك، تُقرأ آلياً)
   — ضروري بشكل منفصل تماماً، لأن Minecraft لا يكتب هذه الإحداثيات في أي
   مكان أصلاً، لا في الكونسول ولا حتى عبر خادم HTTP أعلاه (الذي يعرض
   الحالة اللحظية فقط، لا التاريخ).

الإحصائيات الكاملة (وفيات كعدد، قتل، مسافات) تعمل دائماً بدون هذه
الإضافة، لأنها تُقرأ من ملف إحصائيات قياسي منفصل لا علاقة له بها.

```bash
cd PanelDataLogger
mvn package   # التفاصيل والتعديلات المطلوبة على pom.xml في PanelDataLogger/README.md
cp target/PanelDataLogger.jar /opt/minecraft/plugins/
```

بعد إعادة تشغيل السيرفر، تأكد أن `PANEL_HTTP_PORT` في `.env` الخاص
باللوحة يطابق `port` في `plugins/PanelDataLogger/config.yml` (كلاهما
`28281` افتراضياً)، ثم تحقق من الجهاز نفسه:

```bash
curl http://127.0.0.1:28281/health   # المتوقع: {"status":"ok"}
```

التفاصيل الكاملة في `PanelDataLogger/README.md`.

## النشر

**Docker** (لم أبنِ الصورة على جهازي لعدم توفر Docker هنا، فجرّبها قبل الاعتماد عليها):

```bash
cp .env.example .env     # عدّل ADMIN_PASS وSESSION_SECRET
docker compose up -d     # يشغّل اللوحة وJava في حاوية واحدة، والبيانات في ./data
```

اللوحة تتحكم بالسيرفر عبر tmux، لذلك تعمل اللوحة والسيرفر في الحاوية نفسها. لتشغيل أكثر من سيرفر شغّل نسخة من الخدمة لكل سيرفر بمنفذ ومجلد بيانات مختلفين.

**systemd**: انسخ `deploy/mc-panel.service` إلى `/etc/systemd/system/` وعدّل المستخدم والمسارات. **HTTPS**: قوالب جاهزة في `deploy/Caddyfile` و`deploy/nginx.conf`، وضع `COOKIE_SECURE=auto` في `.env`.

**الاختبارات**: `npm test` (تشغّلها GitHub Actions على Node 18/20/22).

**حدود هذا الإصدار**: اللوحة تدير سيرفراً واحداً (للشبكات شغّل لوحة لكل سيرفر)، ولا تدعم Velocity/BungeeCord كنوع سيرفر، ولإضافة لغة جديدة انسخ `locales/en.json` إلى `locales/<code>.json` وترجم القيم (حقول `meta.*` تحدد الاتجاه والخط).

## ملاحظات أمنية

اللوحة تعطي تحكم كامل بالسيرفر: تشغيل وإيقاف، حذف ملفات، تنفيذ أوامر console. لا تعرّض المنفذ مباشرة على الإنترنت. الأفضل reverse proxy (nginx أو Caddy) مع شهادة HTTPS فوقه، أو تقييد الوصول بجدار ناري أو VPN.

الكوكيز مضبوطة بـ `httpOnly` و`sameSite: strict`، لكن بدون `secure` صريح في الكود. الحماية الكاملة تحتاج HTTPS فعليًا في طبقة الـ reverse proxy.

غيّر `ADMIN_PASS` الافتراضي قبل أي استخدام حقيقي. فلترة الأوامر ومدير الملفات فيهم حماية من path traversal وحقن الشل، لكن هذا لا يغني عن تقييد من يوصل للوحة أساسًا.
